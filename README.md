# SelfBank

Особиста система управління грошима: дашборд зі статистикою та графіками, облік
операцій, бюджети, регулярні платежі, цілі накопичень і борги. Все збирається в
**один Docker-образ** — один процес, один контейнер, база в одному файлі.

---

## Швидкий старт

```bash
git clone <repo> selfbank && cd selfbank
cp .env.example .env
npm install && npm run hash-password      # згенерує AUTH_PASSWORD_HASH і AUTH_SECRET
# вставте надруковані рядки у .env
docker compose up -d --build
```

Відкрийте http://localhost:3000 і увійдіть логіном з `AUTH_USERNAME` (типово `admin`).

Без compose:

```bash
docker build -t selfbank .
docker run -d --name selfbank -p 3000:3000 \
  -e AUTH_USERNAME=admin \
  -e AUTH_PASSWORD_HASH='$2b$12$...' \
  -e AUTH_SECRET='<32+ символи>' \
  -v selfbank-data:/data \
  --restart unless-stopped selfbank
```

> **Важливо про bcrypt-хеш.** У файлі `.env` знаки `$` треба екранувати як `\$`
> (`AUTH_PASSWORD_HASH="\$2b\$12\$..."`), інакше dotenv підставить замість них
> порожні значення і вхід завжди відхилятиметься. `npm run hash-password` друкує
> обидва варіанти: екранований для `.env` і звичайний для `docker run -e`.
> Застосунок розпізнає обидва й дає зрозумілу помилку, якщо хеш пошкоджений.

## Що всередині

| Розділ | Що робить |
|---|---|
| **Дашборд** | Баланс, доходи/витрати за період, чистий потік, норма накопичення; динаміка балансу з прогнозом, доходи vs витрати по місяцях, витрати за категоріями, бюджети, найближчі платежі, цілі й борги |
| **Операції** | Додавання доходу / витрати / переказу, фільтри за датою, типом, рахунком, категорією та сумою, пошук по нотатках, CSV-експорт вибірки |
| **Рахунки** | Кілька рахунків у різних валютах, архівування, початковий баланс |
| **Категорії** | Два рівні вкладеності, колір і іконка; кольори використовуються у графіках |
| **Бюджети** | Місячний ліміт на категорію (або загальний), перенесення залишку, попередження й перевищення |
| **Регулярні** | Підписки, зарплата, оренда — автоматично або з ручним підтвердженням |
| **Цілі** | Прогрес за балансом привʼязаного рахунку або за позначеними операціями, скільки відкладати на місяць |
| **Борги** | Хто кому винен, прогрес погашення, прострочення |
| **Аналітика** | Середні витрати, топ-витрати, джерела доходів, таблиця місяць × категорія, прогноз |
| **Налаштування** | Базова валюта, курси валют, повний експорт/імпорт |

### Поле суми — це калькулятор

У полі суми можна писати вирази: `1200+350`, `450*3`, `(100+200)/2`.
Під полем одразу показано, що саме буде збережено. Приймаються як `1 200,50`,
так і `1200.50`; пробіл — роздільник тисяч.

---

## Гроші та валюти

- **Суми ніколи не зберігаються як дробові числа.** Усе — цілі числа в мінорних
  одиницях (копійки, центи, саторі), кількість знаків залежить від валюти.
- Кожна операція **запамʼятовує курс на свою дату**. Зміна курсу сьогодні не
  переписує звіти за минулі місяці.
- Баланс рахунку — навпаки, величина «на зараз», тому конвертується за
  найсвіжішим курсом.
- Якщо курсу немає, застосунок каже про це прямо (валюта не входить у зведений
  баланс) замість того, щоб тихо порахувати її як нуль.
- Баланси ніколи не денормалізуються: вони щоразу виводяться з операцій, тому
  розсинхронізації не буває.

Курси задаються вручну в **Налаштуваннях**: скільки одиниць базової валюти
коштує одна одиниця іншої.

## Резервні копії

| Що | Де | Для чого |
|---|---|---|
| **JSON-копія** | Налаштування → Експорт | Повний дамп усіх таблиць разом з ідентифікаторами. Відновлює стан один в один, включно з привʼязками операцій до цілей і боргів |
| **Файл бази** | Налаштування → Файл бази | Найточніша копія (`VACUUM INTO`, знімок без зупинки застосунку) |
| **CSV** | Транзакції → Експорт CSV | Звіт по поточній вибірці для Excel, не резервна копія |

Імпорт має два режими:

- **Замінити все** — повністю відновлює стан із копії. Перед заміною
  автоматично створюється страхувальна копія у `/data/backups/`.
- **Обʼєднати** — додає лише те, чого немає. Повторний імпорт того самого файлу
  нічого не змінює: записи зіставляються за природними ключами (рахунок — за
  назвою й валютою, операція — за типом, рахунком, сумою, датою й нотаткою).

## Регулярні платежі

Правила перевіряються при старті процесу та щогодини. Якщо контейнер був
вимкнений тиждень, пропущені операції дозаповнюються **одноразово**: вставка
операцій і зсув курсора відбуваються в одній транзакції SQLite, тому дублікатів
не буває навіть якщо застосунок перезапуститься посеред процесу.

Розклад обробляє короткі місяці коректно: правило «31 числа» дає 31 січня,
28 лютого, **31 березня** — без дрейфу на 28-ме.

Автоматичне проведення вимикається змінною `RECURRING_CRON=off`; тоді операції
створюються кнопкою «Провести зараз».

## Налаштування через змінні середовища

| Змінна | Типово | Призначення |
|---|---|---|
| `AUTH_USERNAME` | `admin` | Логін |
| `AUTH_PASSWORD_HASH` | — | bcrypt-хеш пароля (`npm run hash-password`) |
| `AUTH_PASSWORD` | — | Пароль відкритим текстом; використовується лише якщо немає хеша |
| `AUTH_SECRET` | — | **Обовʼязково**, 32+ символи. Підпис сесійної куки |
| `SESSION_TTL_DAYS` | `30` | Термін життя сесії |
| `COOKIE_SECURE` | авто | `true`/`false`, якщо застосунок за reverse-proxy |
| `DATABASE_PATH` | `/data/selfbank.db` | Шлях до файлу бази |
| `RECURRING_CRON` | `on` | `off` вимикає автоматичне проведення |

Застосунок **не стартує** без `AUTH_SECRET` — краще зрозуміла помилка, ніж
сесійна кука, яку можна підробити.

## Розробка

```bash
npm install
cp .env.example .env            # заповніть AUTH_SECRET і AUTH_PASSWORD_HASH
npm run db:migrate              # застосує міграції у ./data/selfbank.db
npm run dev                     # http://localhost:3000
```

| Команда | Що робить |
|---|---|
| `npm test` | Юніт- та інтеграційні тести (vitest) |
| `npm run typecheck` | Перевірка типів |
| `npm run db:generate` | Згенерувати міграцію зі змін у `src/db/schema.ts` |
| `npm run db:migrate` | Застосувати міграції |
| `npm run hash-password` | Згенерувати `AUTH_PASSWORD_HASH` і `AUTH_SECRET` |

### Структура

```
src/
├─ db/            схема (drizzle), підключення, початкові дані
├─ lib/           гроші, курси, дати, розклади, прогноз, резервні копії
│  └─ queries/    читання з бази: баланси, статистика, бюджети, цілі, борги
├─ actions/       server actions (запис)
├─ app/           сторінки та API-маршрути
└─ components/    UI, форми, графіки
```

Логіка, у якій живуть помилки — розбір сум, курси, розклади, прогноз,
резервні копії, баланси — винесена в чисті функції й покрита тестами.

### Міграції

`src/db/schema.ts` — єдине джерело правди. Після зміни:

```bash
npm run db:generate   # створить drizzle/NNNN_*.sql
```

Міграції застосовуються в `docker/entrypoint.sh` **до** старту сервера: збій
міграції зупиняє контейнер, а не залишає напівробочий застосунок.

## Технології

Next.js 16 (App Router) · TypeScript · SQLite через better-sqlite3 + Drizzle ORM ·
Tailwind CSS v4 · Recharts · Zod · jose + bcrypt.

SQLite обрано свідомо: для особистих обсягів вона швидша за будь-що з мережевим
викликом, бекап — це копія одного файлу, і не потрібен другий контейнер.

Палітра графіків перевірена на придатність для дальтоніків у світлій і темній
темі; доходи й витрати позначені синім і помаранчевим, а не зеленим і червоним,
бо саме ця пара найгірше розрізняється. Усі графіки мають легенду, підписи та
альтернативу у вигляді таблиці.
